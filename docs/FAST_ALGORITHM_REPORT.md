# 低计算量波形算法：设计、对照和验证

日期：2026-09-24。目标板：MSPM0G3507，80 MHz Cortex-M0+、32 KiB SRAM。
目标仍为赛事手册中的 100–400 Hz 正弦、20%–80% 方波、三角、下降锯齿，
输出频率、Vpp 和方波占空比；初赛 10 s、决赛 15 s 包含采集和串口输出。

## 1. 文献与工程取舍

| 路线 | 依据和取舍 |
| --- | --- |
| FFT 和谐波分析 | 手册附带培训材料第 11、16 页提出；固定 4096 点会占用额外频谱缓冲，且仍要解决非正弦谐波与基波混淆。保留为需要时的诊断路线。 |
| YIN/自相关差分 | [原始论文](https://audition.ens.fr/adc/pdf/2002_JASA_YIN.pdf)用差分和累计均值归一化抑制倍频/半频错误。当前工程已有 AMDF 加交越回归和弱证据倍频救援；直接换成完整 YIN 增加计算而没有已知误差收益。 |
| CMSIS-DSP 整段相关 | [Arm 官方 Q15 相关文档](https://arm-software.github.io/CMSIS-DSP/v1.16.0/group__Corr.html)的常规输出长度为 `2N-1`；fast Q15 的 32 位内部累加存在溢出限制。这里只有 128 点循环相位，保留有界 64 位累加并复用模板范数更直接。[TI 的 MSPM0 集成说明](https://software-dl.ti.com/msp430/esd/MSPM0-SDK/1_30_00_03/docs/english/third_party/cmsis_dsp/doc_guide/doc_guide-srcs/Users_Guide.html)可用于后续移植库。 |
| 片上数学加速 | [TI 数据手册](https://www.ti.com/lit/ds/symlink/mspm0g3507.pdf)给出 80 MHz、32 KiB SRAM 和数学加速器。先消除上千次不必要的归一化除法，减少寄存器/驱动依赖；后续以板上周期测试决定是否接入加速器。 |
| **本次方案** | 保持原基波选择、交越回归、128 相位折叠、四类生成模型、仿射 Vpp 的物理解释；只替换粗搜抽样密度与循环相关的重复计算。 |

以上为根据资料与本项目实测所做的工程判断；文献没有为本项目数据提供精度承诺。

## 2. 算法 3 `fast_phase_model`

1. 仍计算 98–402 Hz 所有整数候选延迟的 AMDF，但每隔 8 个样点比较一次，
   算法 1/2 每隔 2 点。每个延迟约从 2048 次差值降到 512 次；交越回归和
   倍频消歧逻辑保留。4096 点、20 kS/s 下，最短周期仍有约 50 个样点。
2. 每类生成模型一次：正弦、三角、锯齿各 1 形状，方波 5×5 种边沿形状，
   合计 28 个。对每一形状扫描 128 个循环相移，按**原始协方差**寻找最大值。
3. 对长度为 128 的循环移位 `T_s`，`sum(T_s)` 和去均值能量
   `sum((T_s-mean(T_s))²)` 均与 `s` 无关。因此同一形状所有相移可共用
   模板范数，且只在最佳相移计算一次 `dot²/(energy_y*energy_t)`。
   新路径把每轮相移重新生成模板、重新算两遍均值/范数、重新作归一化除法
   改成复用单个模板与能量。仍用 `int64_t` 乘累加防溢出。
4. 正常强证据帧直接沿用第一次折叠结果。需要倍频救援时仍评估原算法 2
   的全部候选，随后重新折叠获胜周期并重建 Vpp 模板。类别拒识门限未放宽。

### 计算量和 SRAM

| 项目 | 原算法 2 | 算法 3 |
| --- | ---: | ---: |
| 约 150 个延迟的 AMDF 比较 | 约 30 万 | 约 7.5 万 |
| 每次分类的模板生成 | 28×128＝3584 次 | 28 次 |
| 每次分类的归一化整数除法 | 3584 次 | 28 次 |
| 128 点循环相关 | 28×128 个相移 | 28×128 个相移，模板索引轮转 |
| 普通帧折叠次数 | 2 | 1 |
| 算法对象静态 BSS，主机 `-Os` | 约 14112 B | 14624 B |

算法与 ADC 缓冲（8192 B）合计约 22816 B；旧版 `Debug/TI-game.map`
含应用和 SDK 全局量的 BSS 末端在 SRAM 起始后 22528 B，本次增加 512 B，
**仅作旧 map 估算**约剩 9728 B 给栈等用途；需要 CCS Release 重建后的
新 map 才能确认实际值。无堆分配、无新增浮点运算。

## 3. 精度验证

同一源码的 C 核心由主机编译，固定种子生成的 ADC 数组传给相同 ABI。
`tests/run_all_checks.sh` 包含 2400 帧初赛模型、2400 帧强干扰模型和每条
算法的 200+96 题；含协议/编译检查。赛事手册没有给统一数值误差门槛，
测试门禁自行设初赛频率 ≤0.50%、Vpp ≤8%、占空比 ≤2 个百分点；
挑战组分别 ≤1%、≤12%、≤3 个百分点。类别和有效状态必须正确。

| 数据组 | 算法 1 | 算法 2 | 算法 3 | 算法 3 最坏频率 / Vpp / 占空比误差 |
| --- | ---: | ---: | ---: | --- |
| 固定初赛门禁 | 200/200 | 200/200 | 200/200 | 0.0310% / 4.196% / 0.522 pp |
| 固定挑战组 | 95/96 | 96/96 | 96/96 | 0.0479% / 9.972% / 0.617 pp |
| 初赛随机回归 | — | — | 2400/2400 | 0.0678% / 4.233% / 1.666 pp |
| 强干扰随机回归 | — | — | 2400/2400 | 0.2317% / 5.217% / 0.524 pp |

另在种子 `20260924`、`314159`、`8675309` 上分别重建 200 道门禁和
96 道挑战，算法 3 合计 **888/888**；各组最坏误差见 `tests/results/fast_holdout_*.json`。
对原项目保留的 156 帧 8192 字节采样记录，算法 2/3 的成功状态和类别一致；
其中 151 帧的主要输出完全相同，另 5 帧均为安全拒识，仅内部诊断频率差
约 0.26–0.54 Hz。采样记录并非独立标定真值，不能据此评估真实频率/Vpp 误差。

## 4. 主机耗时（只比较 C 核心）

`tools/benchmark_algorithms.py` 预生成相同的 296 个 ADC 帧，先预热一次，
再交错运行每条路径三遍，共每算法 888 次同步 C 调用。计时排除波形生成、
ADC 采集、串口输出，包含少量 Python/ctypes 调用开销；环境 Linux x86-64，
`cc -O2`，系统调度可影响最大值。原始输出在
`tests/results/benchmark_algorithms.json`。

| 算法 | 中位分析时间 | 95 分位 | 单次最大观测 |
| --- | ---: | ---: | ---: |
| 1 | 2.3031 ms | 2.6752 ms | 9.1521 ms |
| 2 | 4.3536 ms | 4.8755 ms | 10.8428 ms |
| 3 | **0.4197 ms** | **0.5206 ms** | **2.0475 ms** |

算法 3 的主机中位处理时间相对算法 2 降约 **90.4%（10.37 倍）**，
相对算法 1 降约 **81.8%（5.49 倍）**。这不是 Cortex-M0+ 的周期数或
板上最坏时间。没有可用的实物和 CCS/Arm 目标工具链，不能声称已完成
目标板构建、真实模拟精度或 10/15 s 板上计时。

## 5. 复现与现场验收

```bash
bash tests/run_all_checks.sh
python3 -B tools/benchmark_algorithms.py \
  --library tests/waveform_analyzer_host.so \
  --json tests/results/benchmark_algorithms.json
python3 -B tools/compare_recorded_frames.py \
  --library tests/waveform_analyzer_host.so \
  --json tests/results/recorded_frame_parity.json
```

导入 CCS 后执行 Clean/Build，确认新版 `.map` 的 SRAM/栈空间；烧录横幅
应含 `DEFAULT_ALGORITHM=3`。PA15→PA25 接线后以 `RT1`、`RT2`、`RT3`
分别运行 296 题，并使用示波器或空闲 GPIO 在 `PROCESSING` 前后量测每类、
边界频率、最强噪声与倍频救援的最坏耗时。再使用校准信号源和实测时钟/Vref
验证绝对频率、Vpp 和占空比。时钟和参考比例误差、模拟带宽及削顶仍是
算法外的精度限制。
