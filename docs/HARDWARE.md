# 接线、保护和赛前硬件检查

## 1. 最小可用接线

```text
信号发生器 OUT  ---- 1 kΩ ---- PA25 (ADC0.CH2)
信号发生器 GND  -------------- MSPM0 GND
USB-UART RX      -------------- PA10 (UART0.TX)
USB-UART TX      -------------- PA11 (UART0.RX)
触发按键         -------------- PB13 与 GND 之间
```

只有在示波器已经确认输入全程位于 0–3.3 V 时，才允许使用该最小连接。信号发生器端通常应设为高阻负载显示模式；如果仪器按 50 Ω 负载标定而实际接高阻，显示值和实际输出可能相差一倍，必须现场用示波器确认。

## 1.1 自激环路接线（没有信号发生器时）

板载 DAC12 在 **PA15** 上产生测试波形，因此不需要外部信号源就能验证整条
模拟链路：

```text
PA15 (DAC12 输出) ---- 杜邦线 ---- PA25 (ADC0.CH2)
MSPM0 GND  ----------------------- 与电脑/示波器共地
USB-UART RX            ----------- PA10 (UART0.TX)
USB-UART TX            ----------- PA11 (UART0.RX)
```

上电后串口发 `RT`，固件会依次跑完 12 个用例：DAC 产生已知波形 -> 经杜邦线
回到 PA25 -> ADC 采集 4096 点 -> 算法识别 -> 把标称值和测量值逐项对比，
同时把每帧 4096 个采样点回传给电脑。串口发 `R` 则是原有的对外测量。

电脑侧通过板载 USB-UART 收到识别结果和 ADC 样点；若使用独立 USB-UART，按上图
交叉连接 PA10/PA11 并共地。PA15 是 DAC 模拟输出，不能接 UART RX；自激反馈线
应接 `PA15 -> PA25`。PA15 在采集的约 205 ms 内输出模拟波形；UART 在每帧采集
完成后回传识别结果和二进制样点（不是实时模拟输出）。可用
`tools/rt_self_test.py --csv` 落成 CSV 后在电脑绘图；示波器/逻辑分析仪观察
实时模拟输出时直接探测 PA15。

要点：

- PA15 是该封装上 DAC0 唯一可用的模拟输出脚，不需要外接运放，DAC 自带
  输出缓冲可以直接驱动 PA25；
- **不需要**串联 1 kΩ，也不要再对地并联电容：自激时 PA15 就是信号源本身，
  串电阻或加电容只会让波形变钝，反而拉低分类余量；
- DAC 和 ADC 都以 VDDA 为参考，参考电压的绝对误差在两端互相抵消，所以
  Vpp 的对比可以卡得很紧（实测容差 5%）；
- 非自激状态下固件会把 DAC 输出缓冲置成高阻，因此自检用的杜邦线**可以
  一直挂着**，不会干扰外部信号源的对外测量；
- 若 `RT` 全部报 `SIGNAL_TOO_SMALL`，先确认杜邦线接的是 PA15 而不是别的脚，
  以及是否共地。

用示波器观察自激波形时，直接探头接 PA15 即可；每个用例输出约 205 ms
（4096 点 / 20 kHz），示波器用普通余辉就能稳定看到。

## 2. 可选分立前端

赛事允许分立阻容和裸芯片运放，不允许成品采集/波形分析模块。初赛优先保证形态不被前端改变，建议按以下顺序逐级增加：

1. **基础保护**：确认输入范围合规后，在输入端串联 1 kΩ 限流；
2. **轻度限带**：串联 2.2 kΩ、PA25 对地 10 nF，截止频率约 7.2 kHz；
3. **需要电平搬移/缩放时**：使用分立电阻网络和轨到轨输入输出、3.3 V 单电源裸芯片运放自行搭建缩放/偏置电路，并保留 0.1–3.2 V 裕量。

7.2 kHz RC 对 400 Hz 基波衰减很小，也不会明显破坏规则允许的方波边沿；它主要削弱远高于信号带宽的尖峰。不要为了“滤得更干净”把截止频率降到 1 kHz 左右，否则 400 Hz 方波和锯齿的必要谐波会被严重削弱，分类形态反而变差。

## 3. 上电前检查表

- [ ] MSPM0G3507 板和信号发生器已经共地；
- [ ] PA25 输入最小值 ≥ 0 V，最大值 ≤ 3.3 V；
- [ ] 串联保护电阻已焊接，杜邦线无松动；
- [ ] 若使用独立 USB-UART，PA10/PA11 与其交叉连接且串口地共地；板载 XDS110 虚拟串口无需另接 UART 杜邦线；
- [ ] 串口为 115200、8 数据位、无校验、1 停止位；
- [ ] PB13 按键只把引脚拉到 GND，不外加 5 V；
- [ ] 使用 100、250、400 Hz 各跑一次；
- [ ] 使用 20%、50%、80% 占空比方波各跑一次；
- [ ] 记录 1 Vpp 标准输入的 Vpp 输出，用于确认 VDDA 标定；
- [ ] 连续触发 20 次，确认没有卡在 `CAPTURING`；
- [ ] 自激检查：PA15 已短接到 PA25，发 `RT` 得到 `RT-DONE,pass=12,fail=0`；
- [ ] 最终 CCS Clean + Build 无警告，并烧录刚生成的固件而非旧 Debug 目录中的文件。

## 4. 现场快速诊断

| 串口现象 | 最可能原因 | 处理 |
| --- | --- | --- |
| 完全无启动信息 | TX/RX 接反、未共地、未运行新固件 | 检查 PA10→USB-UART RX 和 GND |
| 有启动信息但发 R 无响应 | RX 未接到 PA11 | 用 PB13 触发并检查 RX |
| 一直停在 CAPTURING | TIMA0→ADC 事件或 ADC 中断配置未生成 | CCS Clean，打开 SysConfig 检查后重新 Build |
| SIGNAL_TOO_SMALL | 幅度太小、输入未接、地线断开 | 示波器检查 PA25 |
| `RT` 全部 SIGNAL_TOO_SMALL | PA15 没接到 PA25，或接错脚，或未共地 | 万用表确认 PA15↔PA25 导通 |
| `RT` 报 RT-CHECK FAIL 且 type_ok=0 | 波形被前端改形（串了电阻或对地电容） | 去掉 PA15 与 PA25 之间的额外元件 |
| 发 `RT` 无响应 | 固件不是含 RT 的新版本 | 重新 Build 并烧录 |
| ADC_HIGH_CLIPPED / ADC_LOW_CLIPPED | 输入达到/超过 ADC 两端 | 立即降低幅度/调整偏置 |
| ADC_SAMPLE_INVALID | 注入数据超过 12 位范围 | 检查串口端序和采样缓冲 |
| CLASSIFICATION_AMBIGUOUS | 最佳/次佳模板过于接近 | 降低噪声、检查前端滤波后重测 |
| PERIOD_NOT_FOUND | 波形未稳定、频率不在范围、噪声或接触问题 | 等信号稳定后重测并检查接线 |
| FREQUENCY_OUT_OF_RANGE | 实际频率超范围或错误多边沿 | 检查发生器频率，必要时加轻度 RC |
| 类别正确但 Vpp 有固定比例误差 | VDDA 或发生器负载标定问题 | 实测 VDDA，检查 50 Ω/Hi-Z 设置 |

## 5. 与算法接口的校准

新版算法不在输出端硬编码补偿，采集侧必须通过 waveform_frame_t 传入：

- 实际 sample_rate_millihz；
- 实测 adc_reference_microvolts；
- 前端的 frontend_gain_ppm。

若使用 SYSOSC 标称频率且不校准，数据手册给出的时钟精度会直接限制频率绝对误差；若用 VDD 作 ADC 参考而仍固定填 3.300 V，VDD 的实际偏差会原样进入 Vpp。完整字段定义、增益方向和验收步骤见 [采集-算法接口协议](ACQUISITION_ALGORITHM_INTERFACE.md)。
