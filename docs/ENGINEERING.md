# 决赛工程说明与精度分析

本文合并原算法/接口、存档、矩阵和验证文档，描述当前实现。版本：上位机 3.0.0，固件 DUMP v3；兼容 v2，C ABI 2.1.2（0x00020102）。旧版本的失效路径、旧验证结论和缺失文档引用不再作为当前说明。

## 1. 赛事约束与精度口径

上传赛事手册第 3 页要求决赛每例在 15 s 内给出全部结果；两组均是预生成含噪周期波形的循环回放，较强干扰为 30%–50% 噪声峰峰值、约 1.5–3 倍载波带宽，最终参数范围在赛前一周公布。手册没有承诺最终沿用初赛所有参数范围，也没有给出输出小数位上限。本工程保留原 RESULT 字段与命令，只增加十进制位数。

当前 C 分类搜索仍为原来的约 98–402 Hz，针对 100–400 Hz 初赛范围留有边界余量。**拿到决赛公告后必须核对这一范围**；不要把未公布的决赛范围或项目自设 PASS 门限当成官方评分标准。

频率和 Vpp 的目标误差建议明确为相对误差：`|测量/参考−1|`，1 ppm = 10⁻⁶，0.1 ppm = 10⁻⁷。占空比有两种不同口径：`|D测−D真|` 为周期占比的绝对误差，`|D测/D真−1|` 为相对误差；测试矩阵沿用“百分点”。0.0001 个百分点等于 1 个周期占比 ppm，不能混写成相对 duty ppm。

## 2. 时钟排查与结论

### 历史内部时钟配置的证据

- 修改前的 `empty.syscfg` 使用 `SYSCTL.forceDefaultClkConfig=true`；当时的 `empty.c` 没有运行时 SYSPLL/MCLK 切换。原工程使用默认配置，未找到 80 MHz 配置。当前版本已切换至下述 HFXT 路径。
- TI 的 LaunchPad 用户指南 §2.7 明确默认 SYSOSC/MCLK 为 32 MHz。80 MHz 是芯片支持的额定上限，不能把“80 MHz”直接视为超频。
- 原 RO 独立校准测得 fs=20244.764 Hz，而固件线上报告标称 20000 Hz。若仍按标称率计算，`f测/f真=20000/20244.764`，约 −1.209% 的偏差，与“每次稳定偏小、RO 后恢复”的方向和量级相符。
- 原两个拟合参考 fs 为 20244.1931 / 20245.3340 Hz，彼此相差约 56.4 ppm；原独立 250 Hz 验证差约 17.8 ppm。同一历史 ADC 用本版全记录谐波拟合复算得到 20243.9847 / 20245.3658 Hz，差约 68.2 ppm，独立检查差约 18.9 ppm。复算不是重新采集，不能据此发布一份“新实机标定”。

因此，当前最有力解释是**实际采样时基与标称元数据不一致**，可能来自 SYSOSC 本体偏差、温度/供电变化、发生器实际时基或不同捕获时的漂移。不能仅凭文件排除板上烧录了别的旧固件，也不能把漂移全部归因于某一个元件。保持默认 32 MHz 是合适的采集配置，但不会自动得到 ppm 准确度。

### 本版处理

2026-10-16 在 main 同步外部晶振修改，并将 HFXT → SYSPLL → MCLK 路径直接写入 `empty.syscfg`，详见 [外部时钟配置与烧录验证](EXTERNAL_CLOCK.md)。原装 LP-MSPM0G3507 的 Y2 是 **40 MHz**，PLL 生成 32 MHz MCLK，TIMA0 每 50 µs 发布一次事件触发 ADC0，DMA 逐点搬运；ADC 转换时钟为 HFCLK/2。`board_clock.h` 只核验启动状态和时钟源，采集期间不切换时钟、不调整 SYSOSC trim。SysConfig 不启用 SYSOSC FCL；旧 FCL 状态需 BOOTRST 清除，烧录后建议断开全部供电再上电。采样时基不再依赖 SYSOSC/FCL。不依靠 CPU 软件延时生成采样间隔。固件报告标称元数据，校准 flags 仍为 1；只有上位机加载已验证的 RO 校准后才增加校准标志。旧内部时钟校准已备份并清空，首次使用必须重新 RO。

RO 时基拟合从单一阈值交越回归改为全记录 DC + 基波/谐波的双精度联合拟合。保存额外的 `sample_rate_hz_exact`；mHz 字段仅供旧 ABI 和协议兼容。拟合参考仍为独立 100/400 Hz，验证为独立 250 Hz，不使用矩阵真值。报告新增参考 fs 离散度 ppm 和 `absolute_accuracy_verified=false`，现有工程校准合格门限没有伪装成 1 ppm 验证。

### 如何验证实板

烧录本版，确认启动横幅包括 `HFXT=40MHz, PLL=32MHz, CLOCK=EXTERNAL`、V3 / N=8192 / MCLK=32MHz；检查 SysConfig 生成的 CPUCLK、TIMA0 时钟选择、分频、装载值。用 `fs=fTIM/(分频×(LOAD+1))` 对照生成配置，不要拿 CPU 主频代替实际定时器时钟。对计时器发布事件、ADC 完成和 DMA 点数做实板核对；记录 100/250/400 Hz 独立测量、温度和供电。通过具有明确时基规格的计数器或独立参考验证实际输出频率。UART 到达时间带有传输和调度延迟，不能用作 ppm 采样时钟标定。

## 3. 为什么三个量都到 0.1 ppm 不能靠这份硬件保证

### 频率

12 位 ADC 不阻止通过长记录获得亚采样频率估计；本版无噪声实验中一些频率误差小于 0.1 ppm。但绝对频率误差近似为：估计器误差 + 采样时钟校准/漂移 + 参考源实际频率误差。程序不能从单个未知输入信号同时辨认“输入频率变了”还是“采样时钟变了”。

TI 数据手册 §7.9.1 对未开 FCL 的 32 MHz SYSOSC 给出跨工作范围约 −2.6% 至 +1.8%，是百分比级规格；外置 0.1% ROSC 配合 FCL 也不是 0.1 ppm 标准。即使 SYSOSC 经 PLL 倍频到 80 MHz，基准的相对频偏仍会传递过去。外置晶体/参考时钟是否实际焊接、使能以及其温漂，需要针对手中板卡核对。

### 峰峰值

3.3 V / 4095 ≈ 805.86 µV 每码；对于 1.5 Vpp，1 ppm 是 1.5 µV，0.1 ppm 是 0.15 µV。平均和已知形状拟合能获得亚 LSB 估计，但不会补回 INL、Vref 漂移和已削顶的信息。TI 数据手册 §7.12.3 的 ADC INL 上限为 ±2 LSB、DNL ±1 LSB；三点增益/零偏校准不会完整纠正 INL。

特别是几乎无噪声且锁相的方波，上/下平台可能长期停留在两个整数码。它们之间的真实电压仍存在量化区间，反复采同一相位并不会增加有效分辨率。本版独立无噪声实验的方波 Vpp 误差约 244 ppm，正是这种现象，而不是显示位数不够。

即使假设已消除所有系统误差，对已知频率正弦、独立高斯噪声，幅值相对标准差约为 `(σ/A)√(2/N)`。例如 σ/A=2%、N=8192，仍约 313 ppm；到 1 ppm 理论上需约 8×10⁸ 个独立样本。比赛噪声可能带限且循环回放，相干噪声甚至不按独立白噪声公式平均。这是量级说明，不是本设备的置信区间。

### 占空比

占空比按重建高/低电平中点的上升和下降交越定义，必须分别估计两种边沿；上升时间不等于下降时间时不能做对称修正。边沿很快且两侧之间没有 ADC 点时，单帧只能给出边沿所在区间，不能凭插值捏造真实时间。

200 Hz、50% duty 下，1 ppm 相对占空比要求约 2.5 ns 的高电平宽度精度，0.1 ppm 约 250 ps；当前 ADC 间隔为 50 µs。多周期与模型拟合能越过采样间隔，但前提是边沿模型正确、噪声低、时基和模拟延迟稳定。若某边沿不足两个采样间隔，本版记录 `edge_identifiable=false`；更多小数不会消除不可辨识性。

## 4. 本版算法改进

### 采集长度与时间预算

每帧从 4096 增至 8192 点；标称连续采样时间 0.4096 s，缓冲区 16 KiB，UART 16384 字节的理论传输约 1.422 s，单帧仅采集和载荷上传约 1.832 s。默认 R 4 帧的理论下限约 7.33 s，再加帧头、拟合、校验和存盘；真实耗时必须在比赛电脑验收。固件 ADC/DMA 500 ms 失败保护保留，完整计数在标称 409.6 ms 内完成，留有余量。

C 分类与已有拒识门禁仍使用连续记录前 4096 点，保持原 ABI、原静态工作区和已验证分类行为；Python 精度路径使用完整 8192 点。完整帧的超量程码和削顶也检查，后半段故障不能隐藏在分类窗口之外。C 的周期数/模型分数描述分类窗口；`measurement_sample_count` 描述精度使用的点数。

### ADC 输入建立时间

SysConfig 的 sampCnt=1 表示每次 DMA 触发传输一个 ADC 结果，并非采样保持时间；不能据此判定原保持窗口过短。本版在 SYSCFG 初始化之后、定时器停止且 ADC 转换关闭时，把 SCOMP0/1 寄存器计数统一设为 32，再开启转换。采样时钟 divide-by-2 保留；实际保持时间应根据生成的 ADC 时钟源计算，不能拿 CPUCLK 直接代替。在 4–48 MHz ADC 时钟及 /2 配置下，32 计数的保持窗口约 1.33–16 µs，仍应结合转换时间在实板确认低于 50 µs 周期。这个设置增加对源阻抗和输入电容的建立裕量，不是硬件平均，也不保证消除 INL 或模拟带宽误差。更改保持配置后旧校准可能不再完全适用，必须用本版固件重新 RO 验证。

依据：[TI 对应 G1X0X/G3X0X DriverLib ADC12 文档](https://software-dl.ti.com/msp430/esd/MSPM0-SDK/latest/docs/english/driverlib/mspm0g1x0x_g3x0x_api_guide/html/group___a_d_c12.html)。不同 MSPM0 系列的采样时间公式有差异，不能套用 GX51X 的条目。

### 浮点校准

原始 UART、LE16 ADC 和线上元数据原样保存。C 分类器保留一个经过原仿射校准和取整的副本，维持既有接近电源轨的门禁；原始 0/4095 码仍保留。**频率精修、Vpp 和 duty 的计算输入始终为 `(raw−offset)/scale` 的 float64 样本，绝不使用这个分类副本。** 最终频率使用未取整的 fs，Vpp/DC 使用连续计数和双精度单位换算。

### 频率与占空比

- 正弦：局部搜索频率；每个候选同时重新拟合 DC 与 1–7 次谐波，减少非整数窗口泄漏和已存在谐波的频率偏差。FFT/原 C 结果仅为初值，不用 FFT 格点作为答案。
- 三角：谐波频率种子之后，同时拟合频率和连续相位的三角模型；残差或搜索边界不可靠时保留谐波解。
- 方波：联合拟合 f、相位、duty、rise、fall，DC/幅值由线性最小二乘消元。rise/fall 独立，不要求对称。模型不满足残差门禁时保留后备频率/原 duty。重建幅值直接复用可靠的联合边沿参数，避免粗搜索再次扰动边沿。
- 锯齿：稳定斜坡场景用“每采样点斜率 / 重置跳变量”估频，拟合连续斜坡和已观察到的周期编号；重置数、方向、幅值或残差不可靠时回退 C 周期估计。这个方法不声称知道采样间的真实重置相位。

新增估计器仅接收样本、元数据和 C 分类初值。不读取 case_id、真值、失真标签、仪器设定值或 PASS 门限。没有按 100/200/400 Hz 或矩阵网格吸附答案。

### 峰峰值与干扰

保留原周期/谐波、AM 和独立相干音调重建及两半记录一致性门禁。周期模型的 Vpp 从固定 4096 点网格的 max/min 改为：网格定位局部极值、连续局部优化、检查三角顶点/方波边沿/锯齿跳变两侧。网格现在是搜索初值，而不是幅度分辨率上限。

纯周期结果对应重建干净周期的完整摆幅；AM / 非整数音调结果沿用“当前采集记录的干净包络”定义，目前其极值仍在记录采样时刻求取。它们不能被解释成未观察到的无限时间调制包络极值。削顶后的输入无法唯一恢复削顶前摆幅；可观察的信号形状失真与 ADC 削顶是两件不同的事。

### 多帧 R

默认 4 帧、可选 1–8，每帧独立拟合和存档。类别相同且频率/幅值/duty 稳定才取各参数平均，最终只打印一条 RESULT。诊断保存逐帧标准差；该数不包括时基、参考电压、模型偏差或相干回放噪声，不能作为绝对准确度保证。RT/RO 仍每例运行一次相同单帧算法，原矩阵维持 296 项。

上位机限制小型 BLAS 拟合为单线程，减少多核线程启动开销；C 调用仍由 Engine 的互斥锁串行执行。R 的 15 s 总预算覆盖采集/算法/存档，任何一帧拒识、稳定性失败或预算耗尽都不提交此前的部分结果。PB13 主动触发仍支持单帧上传和分析。

## 5. 串口、Python 与 C 接口

### 固件 ↔ 上位机

UART 115200、8-N-1。上位机只发送单字节 ASCII `R`，不附换行；固件也接受 r/D/d。RO、RT、Q 由上位机本地处理。

当前固件成功帧如下，FNV、seq 为实际十进制 uint32：

```text
CAPTURING\r\n
DUMP,proto=3,bytes=16384,fnv1a=<uint32>,seq=<uint32>,fs_millihz=20000000,vref_uv=3300000,gain_ppm=1000000,adc_max=4095,flags=1\r\n
<16384 个二进制字节，8192 个 LE16 ADC 码>
DUMP_END\r\n
READY\r\n
```

载荷紧接帧头 CRLF，载荷之后直接是 DUMP_END，中间没有额外换行；只能按长度读取二进制。帧头恰好九个字段，不允许重复、缺失或未知字段。v2 仅接受 bytes=8192，v3 接受 bytes=8192 或 16384，其他长度拒绝，不允许任意分配内存。

FNV-1a 仅覆盖载荷字节：初值 2166136261，每字节 `hash=((hash XOR byte)×16777619)&0xffffffff`。先保存线上字节，再校验长度、FNV、DUMP_END/READY。板端错误输出 ERR_ADC_DMA 和 READY，不输出成功 DUMP。

| 字段 | 单位/约束 |
| --- | --- |
| fs_millihz | 标称采样率 mHz；20000000 表示 20 kS/s |
| vref_uv | 标称参考 µV；3300000 表示 3.3 V |
| gain_ppm | ADC 引脚交流幅值 / 被测输入交流幅值 ×10⁶；1/2 分压为 500000 |
| adc_max | 4095 |
| flags | bit0 连续，bit1 校准时基，bit2 校准参考，bit3 硬件平均 |
| seq | 重启后可重复，不能作为全局 ID |

### Python

`tools.host_waveform.Metadata` 保留原七个字段，另有主机字段：`sample_rate_hz_exact`、`adc_scale`、`adc_offset_counts`、`payload_bytes`、`protocol_version`；它们不在串口帧头，不改变 C ABI。新增字段缺省值对应旧 v2 / 无校准。

```python
payload, metadata, record = host.receive_frame(port, store=store)
api = build_api()
# 完整波形分析调用必须由调用方的公共锁串行化。
line, details = host.analyze(api, payload, metadata)
```

`line` 仍为内部五列 type,Hz,V,%,DC，不加 RESULT。成功 `details` 增加 `frequency_hz`、`vpp_v`、`duty_fraction`、`dc_offset_v`、`precision_timing` 和样本数；原整数字段仍保留为兼容视图，测试和最终输出优先使用浮点字段。`carrier_result` / `c_timing_result` 保存原 C 阶段值。拒识仍返回 `unknown,0,0,0,0` / ok=false。

调用 `analyze` 本身不重新验证载荷 FNV；外部数据应先走 receive_frame 或自行核验。原 C 的三路径有共享静态空间，不能无锁并发。主机库架构与 Python 位数必须匹配。

### C ABI

`waveform_frame_t`、`waveform_result_t`、导出名、枚举和默认对齐保持原状，头文件为唯一结构定义。`ti_waveform_abi_version/frame_size/result_size` 三项探针仍必须匹配 0x00020102 和 ctypes 结构大小。

C 分类入口最多 4096 点；独立 C 调用者不能把 8192 直接传给这个入口，也不能把整数 C 结果当作 Python 精修后的答案。当前上位机自行检查整个长帧，传前 4096 点做分类，再用全帧精修。

| status | 含义 |
| ---: | --- |
| 0 | 有效 |
| 1 | 幅度过小 |
| 2 / 5 | 高端 / 低端削顶 |
| 3 | 无稳定周期 |
| 4 | 超出当前频率范围 |
| 6 | ADC 码超量程 |
| 7 | 分类不明确 |
| 8 / 9 / 10 | 参数 / 元数据 / 点数错误 |

stdout 只打印成功 RESULT；拒识和异常在 stderr / server.log。完整有效结果行打印并 flush 的时刻为提交时刻。增加小数位没有改变字段个数、波形命名、单位或非方波的占空比 0。

## 6. 校准与存档

`algorithm_parameters.json` 继续使用 schema=1；旧参数按原校验和读取，新参数可带 fs 的双精度字段。核对 nominal_metadata 的 fs/vref/gain/adc_max，损坏、不匹配或来源校验失败即报错；不静默回退。更换为同样标称参数的另一块板无法仅靠这四项识别，操作者必须重新 RO。

原成功校准保留，是已有板卡的可用初始值。新 RO 必须先通过独立 DC / AC / 时基验证才原子发布；中断或失败不覆盖旧文件。成功标定后矩阵失败也不撤销它。发生器 ARB 的 gain/offset 校准仍独立于 ADC 标定，只用于发生器命令；不向比赛 R 输出再乘发生器系数。

| 每帧文件 | 含义 |
| --- | --- |
| samples.adc.bin | 原始 LE16 ADC，v2 8192 字节或 v3 16384 字节 |
| capture.json | 线上 metadata、完整算法和判定、校准来源 |
| samples.calibrated.f64.bin | 可选的校准后 float64 计数，<f8 编码，每点 8 字节 |
| samples.csv | 可选原始 ADC 逐点 CSV |

`analysis_payload_file` 指向 **原始** samples.adc.bin，`analysis_metadata` 带仿射校准和精确 fs。复算用这一对重新调用 analyze，让转换只发生一次。f64 文件用于检查连续校准值，**不能作为 LE16 载荷传给 analyze**，也不能再对其套用校准。原始 FNV/metadata 不改写。R 多帧的成员都保留独立分析结果，`r_batch` 保存汇总输出、标准差、总时间和成员路径；每个成员的 `display_output` 留空，防止误认为向比赛提交了多条结果。

RT 报告有 matrix/results.json/results.jsonl/results.csv/summary.json 和全部 ADC。原真值、设定 DC、文件顺序、FNV 和逐帧判定由 verify_rt_archive.py 核对。CSV 不用终端舍入后的数值作判定。

RO 报告保留 SCPI 日志、仪器身份、原 RT 码、上传 DAC 编码、字节核验结果、原始 UART、独立 ADC/ARB 校准以及全部实采结果。v2.1.2 的原完整历史会话已收拢为 evidence/original_ro.zip。旧会话里的校准 ADC 仍是原旧实现的 LE16 编码，读取旧数据时应遵守它自身的 encoding/analysis_metadata；历史复算工具从原 raw 与原 calibration 出发，不重复补偿。

SDG6022X-E 固件 6.01.01.37R6 的具名 USER 波形字节回读限制及原兼容路径保留；没有回读能力不伪称逐字节一致。RO 的发生器输出在完成/异常/中断后关闭，失败关闭会记录错误。

## 8. 若继续冲击 ppm，优先级应怎样安排

1. **先获得可追溯参考与误差预算。** 确认发生器实际频率/电压、负载与接线，不仅是面板设定。用独立校准设备或规范的参考源给出不确定度。参考源本身不够准，任何 RO 系数都无法宣称 0.1 ppm。正式比赛不得调赛方仪器参数，所有自备参考标定在实验室完成。
2. **频率优先改时基。** 核对手中 LaunchPad 的 HFXT 晶体是否焊接/连通，测其温漂；若要 1 ppm/0.1 ppm 绝对准确度，需要达到相应规格且可校准的时钟源、温度补偿或外部参考输入。晶体/裸芯片方案需自行确认赛事允许范围；不能使用手册禁止的成品功能模块。PLL 倍频不能代替精密参考。保持 ADC 定时采样及低功耗稳定工作点，记录热机后和温度变化下的 fs。
3. **Vpp 优先改模拟测量链。** 稳定供电与参考、低漂移分压/缓冲、足够采样建立时间、合适抗混叠。用独立精密电压基准/表做覆盖输入范围的多点 DC 扫描与 INL 建模，再用独立多频 AC 参考检查增益/带宽；直流拟合不能证明方波边沿和 400 Hz AC 幅值的精度。本版没有凭空添加没有真实测量支撑的 INL 查表。若继续坚持 0.1 ppm，需要先确认这种 12 位片内 ADC/参考/前端架构在温漂、线性和比赛时间内是否有可行预算。
4. **增加有效信息，而非只增加采样频率。** 已把连续记录加倍，并提供多帧平均；若下一步做持续 DMA 分块流，应增加实际连续观测时间且带块号/丢包检查。115200 UART 会成为传输瓶颈，改波特率必须同时验证 XDS110、PC 和完整性。固定点数下提高 fs 反而缩短记录、减少周期；不能因此声称频率更准。若噪声随原周期锁定回放，必须评估相干噪声不可分问题。
5. **占空比单独做边沿实验。** 在 20/50/80% duty、独立 rise/fall、不同采样相位下检查中点交越误差。抗混叠滤波对方波、三角和锯齿的形状与边沿延迟必须纳入模型；滤波只能抑噪，不能随意牺牲被测定义。若采用比较器/定时器原始边沿捕获，仍须独立标定门限、迟滞、传播延迟和上下边沿不对称；板上可只上传原始时间戳，计算仍放在 PC，但它是需要新增硬件和固件验证的下一版，当前包未声称具备。
6. **按独立验证选策略。** 每种配置在未知频率/相位/噪声上重复测量，报告带符号偏差、最大误差、温漂、重复性和 15 s 总时间。不要用原 296 项题目参数训练校准系数或放宽门限。R 参数统一使用，不能在比赛样本看到答案后临时吸附频率/幅值/duty。
