# 2026-09-25 RT3 自激测试失败分析与修正

## 结论

`Serial Debug 2026-09-25 190036.txt` 的 19 个 FAIL 不是算法 3 的分类或频率
能力突然退化。19 题全部满足：

- `type_ok=1`；
- `freq_ok=1`；
- 方波题 `duty_ok=1`；
- 只有 `vpp_ok=0`；
- 标称 Vpp 只取 77 mV 或 129 mV；
- 题库的 `center_mode=2`，即原固件把波形推到 DAC 上电源轨附近。

实测 Vpp 比题面标称值低约 10–15 mV。由于 77 mV 题的 8% 门限只有
6.16 mV，129 mV 题的门限只有 10.32 mV，这个固定量级的模拟压缩会让小信号
稳定失败；每题重测 18 次也不会改变结果。

## 根因

旧 `rt_load_case()` 只防止数字码越过 0/4095。高电平模式把中心设为：

```text
center = 4095 - (半幅 + 噪声余量 + 16)
```

因此波形上沿通常只离满量程约 16 个码，约 13 mV。MSPM0G3507 数据手册的
DAC 线性度规格有效输出范围是 **0.3 V 到 VDDA-0.3 V**；数字码合法不等于
模拟缓冲仍在线性区。日志里的 DAC 1024/3072 静态预检正常，只能说明中间
量程连线和增益正常，不能证明靠近 VDDA 时仍能保持小信号摆幅。

算法 2 在旧日志同一题上的结果与算法 3 几乎相同。例如第 2 题旧算法得到
118053 µV，算法 3 最新得到 118046 µV，相差仅 7 µV。因此这不是算法 3 的
稀疏 AMDF 或快速模板相关引入的 Vpp 回归。

## 为什么看起来“以前 RT1/RT2 没这么多”

历史证据实际分成两类：

1. 主机数字回归直接把理想 ADC 数组送进算法，没有 DAC 输出缓冲，也就没有
   近电源轨压缩；所以算法 1/2 的自编题都显示 200/200。
2. 真实 PA15→PA25 的旧日志并非零失败：
   `Serial Debug 2026-09-23 203809.txt` 有 32 个 FAIL，其中 24 个是同类
   Vpp-only 失败，另外 8 个是旧题库把 20 周期生成成 97.656 Hz 导致拒识。

算法 3 的首次板测有 36 个 FAIL；随后 100/400 Hz 分数相位修正和重测机制
消除了边界频率、偶发拒识等问题，最后只剩 19 个确定性的高电平小幅度 Vpp
失败。也就是说最新结果不是比 RT1/RT2 更差，而是把共同的自激发生器问题
暴露得更集中。

## 修正

- 对能够放入线性窗口的题，在 DAC 上下端各保留 0.3 V 余量；
- 中心位置的 low/high/random 变化限制在线性窗口内；
- 把噪声和 challenge 附加谐波/调幅的最大包络计入中心规划；
- 包络本身超过 2.7 V、无法完整放入线性窗口时，回到全量程内居中，不主动
  为了“靠近电源轨”而削顶；
- `RT-CASE` 新增 `center_code` 与 `linear_guard`，便于确认某题的播放条件；
- 主机固件逻辑测试逐题生成码流，验证 `linear_guard=1` 的所有样点确实位于
  0.3 V 到 VDDA-0.3 V 对应码域。

修正没有放宽 8%/12% Vpp 门限，也没有在算法输出端乘补偿系数；它改的是
错误的自激激励条件。最终仍需在板上 Clean/Build/烧录后重新跑 RT1/RT2/RT3，
确认实际硬件的 296 题汇总。
