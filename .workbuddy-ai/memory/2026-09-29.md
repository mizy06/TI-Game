## 发现的环境异常（重要）

`git fetch` / `git update-ref` **无法在 `refs/remotes/**` 下留下 ref 文件**，且无法在 `refs/heads/`、`refs/remotes/` 下**新建子目录**：

- 命令返回 exit 0（报告成功），`git fetch` 也会打印 `[new branch] main -> origin/main`，但 `git rev-parse` / `show-ref` 立刻找不到该 ref。
- **reflog 却会正常写入**：`.git/logs/refs/remotes/origin/*` 有完整记录。
- 空的父目录会被移除（git 的 `try_remove_empty_parents` 行为）。
- `refs/heads/zzz`（直接子节点）、`refs/tags/*`、`refs/foo/bar`（新建命名空间）都正常 → 只有 `refs/remotes/**` 和新子目录受影响。
- 用 shell 直接写文件（`printf hash > .git/refs/remotes/origin/main`）**可以正常持久化**，且 git 能读到。

**绕过方法**：fetch 之后用直接写文件的方式补齐远程跟踪 ref：

```bash
mkdir -p .git/refs/remotes/origin/algorithm
printf '%s\n' <hash> > .git/refs/remotes/origin/main
printf 'ref: refs/remotes/origin/main\n' > .git/refs/remotes/origin/HEAD
```

同理，需要新建的本地分支（如 `codex/hardware-serial-dma`）也要用直接写文件创建，`git branch` 会静默失败。

怀疑与 WorkBuddy 沙箱/后台快照进程有关（同时观察到非本会话触发的 `.git/info/refs` 被 `update-server-info` 重写）。根因未最终确认。
